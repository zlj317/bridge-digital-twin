## 1. 环境要求

| 组件 | 版本 | 用途 | 必需性 |
|---|---|---|---|
| Node.js | ≥ 20（实测 22 / 24 可用） | 前端 Vite 开发、类型检查、打包 | 方式一必需 |
| npm | ≥ 10 | 依赖管理 | 方式一必需 |
| JDK | 17 | Quarkus 3.8 编译运行 | 方式二/三构建时必需 |
| Maven | ≥ 3.9 | 后端构建 | 方式二必需 |
| Python | ≥ 3.11 | SimPy 仿真器 | 仿真必需 |
| Docker / Compose | ≥ 24 / v2 | 全栈一键部署 | 方式三必需 |
| 浏览器 | Chrome / Edge 支持 WebGL2 | 3D 渲染 | 必需 |

**资源建议**：单机 4C / 8G。Compose 中容器内存上限合计约 5G；前端 3D 视口建议独显或支持 WebGL2 的集成显卡。

## 2. 方式一：零中间件演示（推荐，最快看到效果）

```bash
cd frontend
npm install
npm run dev
```

打开 `http://localhost:5173`。

预期：加载遮罩从 8% 到 100% 后隐藏；自动播放 12.5s 五幕动画；顶栏显示「本地仿真 ｜ 60 FPS」；
左栏桥梁健康监测 5 行、右栏车流与运维 5 行；HUD 四幕时间轴与车流滑块可交互。

此模式使用 `VITE_DATA_MODE=mock`，**不需要任何数据库、MQTT 或后端**，内置数据源完整驱动：
72 台车、150 测点、热力着色、3 次防抖告警与自动恢复、面板数值滚动。

验证构建产物：

```bash
npm run build      # tsc --noEmit && vite build，输出到 frontend/dist
npm run preview    # 本地预览 dist
```

## 3. 方式二：本机全链路联调（无 Docker）

需要 4 个终端。建议按 `后端 → 仿真 → 前端` 顺序启动。

```bash
# 终端 1 · 档案服务 :8081
cd backend/svc-bridge
mvn quarkus:dev

# 终端 2 · 监测清洗服务 :8082（EMQX 不可达时自动降级为本地快照）
cd backend/svc-shm
mvn quarkus:dev

# 终端 3 · 仿真器（--dry-run 可完全不装依赖、不连 broker）
cd simulator
pip install -r requirements.txt
python main.py --dry-run --duration 30
# 正常联调（有 EMQX 时）：
python main.py --density 62

# 终端 4 · 前端 live 模式
cd frontend
cp .env.example .env       # 编辑 .env：VITE_DATA_MODE=live
npm run dev
```

验证后端：

```bash
curl http://localhost:8081/api/v1/bridges/BR-DEMO-01/bootstrap
curl http://localhost:8082/api/v1/bridges/BR-DEMO-01/metrics
curl http://localhost:8082/q/health
```

预期：`bootstrap` 返回含 `bridge / components / cables / segments / lanes / viewpoints / clipPlans / animStages / models / pointTypes / points / inspection / simPlans / metrics` 的整包；
`metrics` 返回 24 个指标字段；`/q/health` 返回 `status: UP`（中间件未启动时 `data.*` 显示 DOWN，属正常降级）。

> 前端 `vite.config.ts` 已配置 `/api/v1` 与 `/mqtt` 代理。若后端不可达，`live` 模式会自动回退到本地数据源并在顶栏提示，不会白屏。

## 4. 方式三：Docker Compose 全栈

```bash
cp .env.example .env
# 需要前端走 live 实时链路时，把 .env 中 VITE_DATA_MODE 改为 live
docker compose up -d
```

首次启动会自动执行：

1. `deploy/postgres/init/01_schema.sql` → 17 张表 + PostGIS / pg_trgm 扩展；
2. `deploy/postgres/init/02_seed.sql` → 与效果图 1:1 的种子数据；
3. `deploy/tdengine/init/01_taos.sql` → `bridge_ts` 库、`shm_metric` 超级表与 11 个子表。

`depends_on` 使用 `condition: service_healthy`，PG / Redis / EMQX / TDengine 健康后才拉起两个服务，避免启动竞态。

```bash
docker compose ps                 # 查看 11 个容器状态
docker compose logs -f svc-shm    # 跟踪清洗日志
docker compose down               # 停止并移除容器（保留卷）
docker compose down -v            # 停止并删除全部数据卷（谨慎）
```

访问入口：

| 地址 | 说明 |
|---|---|
| `http://localhost` | 前端页面（Nginx :80） |
| `http://localhost:18083` | EMQX Dashboard（admin / admin123） |
| `http://localhost:3000` | Grafana（admin / admin123） |
| `http://localhost:9001` | MinIO Console（minioadmin / minioadmin123） |
| `http://localhost:9090` | Prometheus |

## 6. 配置说明

| 文件 | 关键项 | 作用 |
|---|---|---|
| `.env` | `VITE_DATA_MODE=mock\|live` | 前端构建期数据源模式；Compose 默认传入 `live` |
| `.env` | `VITE_API_BASE`、`VITE_MQTT_WS_URL` | API 前缀与 MQTT WebSocket 地址 |
| `frontend/.env` | 同上 | 本地 Vite dev 读取 |
| `backend/svc-bridge/src/main/resources/application.properties` | `quarkus.http.port=8081`、`bdt.storage`、`bdt.pg.*`、`bdt.redis.*` | 端口、仓储模式、外部组件地址 |
| `backend/svc-shm/src/main/resources/application.properties` | `quarkus.http.port=8082`、`bdt.mqtt.enabled`、`bdt.alarm.debounce.up/down`、`bdt.snapshot.interval.ms` | MQTT、防抖次数、快照周期 |
| `deploy/nginx/nginx.conf` | `/api/v1` 分流、`/mqtt` 代理、`/q/health` → svc-shm | 网关路由 |
| `deploy/prometheus/prometheus.yml` | 抓取目标 | 指标采集 |

**注意**：`VITE_*` 是 Vite 构建期变量，修改后必须重新 `npm run build`（或重启 `npm run dev`），刷新浏览器无效。

## 7. 启动自检清单

| # | 检查项 | 预期 |
|---|---|---|
| 1 | `npm run build` | `tsc --noEmit` 无错误，Vite 打包成功 |
| 2 | `mvn -q -DskipTests package`（两个服务分别执行） | 无编译错误，产出 `target/quarkus-app` |
| 3 | `python main.py --dry-run --duration 3` | 每秒打印 `traffic/vehicle/...`，每 2s 打印 150 点 `sensor/raw/...` |
| 4 | 页面加载 | 遮罩消失，顶栏 FPS ≈ 60 |
| 5 | 幕一 0~4.5s | 双塔与拉索线框骨架可见 |
| 6 | 幕四 9.5~12.5s | 桥底剖切、四室内部、右栏「内部透视」6 行测点表 |
| 7 | 点击桥面构件 | 弹出构件档案卡 |
| 8 | 点击「模拟告警」后约 6~10s | 告警弹窗出现，列表 +1，稍后 toast「已恢复正常」 |
| 9 | 浏览器控制台 | 0 error |
| 10 | `/q/health` | `status: UP`，`data` 列出 5 个组件连通性 |

详细验收项见 [06-测试与验收清单](../04-测试与规范/06-测试与验收清单.md)。

## 8. 停止与清理

```bash
# 本地开发：Ctrl+C 逐个停止终端；仿真器支持 KeyboardInterrupt 优雅退出
# 全栈：
docker compose down
# 清理构建产物（可选）
rm -rf frontend/dist backend/svc-bridge/target backend/svc-shm/target simulator/__pycache__
```

数据卷 `pg-data / redis-data / taos-data / taos-log / minio-data / frontend-dist / grafana-data` 默认保留；
只有 `docker compose down -v` 会清除，执行前请按 [07-运维手册](07-运维手册.md) 备份。
