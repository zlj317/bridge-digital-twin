## 1. 服务清单与启停

| 服务 | 容器 / 进程 | 端口 | 启动命令 | 停止命令 |
|---|---|---|---|---|
| 网关 | bdt-nginx | 80 | `docker compose up -d nginx` | `docker compose stop nginx` |
| 档案服务 | bdt-svc-bridge | 8081 | `docker compose up -d svc-bridge` | `docker compose stop svc-bridge` |
| 监测服务 | bdt-svc-shm | 8082 | `docker compose up -d svc-shm` | `docker compose stop svc-shm` |
| 仿真器 | bdt-simulator | — | `docker compose up -d simulator` | `docker compose stop simulator` |
| 前端构建 | frontend-build | — | `docker compose up -d frontend-build` | 同上 |
| 中间件 | 5 个 | 见速查表 | `docker compose up -d postgres redis tdengine minio emqx` | `docker compose stop ...` |
| 监控 | 2 个 | 9090 / 3000 | `docker compose up -d prometheus grafana` | 同上 |

全量：`docker compose up -d` / `docker compose down`（保留卷）/ `docker compose down -v`（**删除数据卷，先备份**）。

本机开发模式：两个 `mvn quarkus:dev` + `npm run dev` + `python main.py`，逐个 `Ctrl+C` 停止。

## 2. 日常巡检

| 频率 | 检查项 | 命令 / 位置 | 正常标准 |
|---|---|---|---|
| 实时 | 容器状态 | `docker compose ps` | 11 个容器 running / healthy |
| 实时 | 服务健康 | `curl localhost/q/health` | `status: UP`；`data` 中外部组件期望 UP |
| 实时 | 清洗计数 | `curl localhost:8082/api/v1/system/stats` | `accepted` 持续增长，`rejected` 占比低 |
| 每小时 | 告警列表 | `curl localhost:8082/api/v1/alarms?status=ACTIVE` | 活动告警已有人跟进 |
| 每小时 | MQTT 连接 | EMQX Dashboard → Clients | `svc-shm-*`、仿真器、前端客户端在线 |
| 每日 | 日志错误 | `docker compose logs --since 24h \| grep -i error` | 无未处理异常 |
| 每日 | 磁盘 | `df -h` / `docker system df` | 卷使用率 < 80% |
| 每日 | 指标趋势 | Grafana | JVM 堆稳定、HTTP 错误率 < 1% |
| 每周 | 备份 | 见 §5 | 备份文件可恢复 |
| 每周 | 时序库保留 | `show databases;` | `bridge_ts` KEEP 365 生效 |

> `/q/health` 把外部组件连通性放在 `data` 中，中间件 DOWN 不会让服务被编排系统误杀；但**运维应以 `data.*` 全 UP 为准**。

## 3. 日志

```bash
docker compose logs -f svc-bridge          # 档案服务
docker compose logs -f svc-shm             # 清洗 / MQTT / 告警
docker compose logs -f simulator           # 仿真报文
docker compose logs --tail=200 nginx       # 网关访问日志
docker compose logs --since 10m            # 最近 10 分钟
```

关键日志线索：

| 关键字 | 含义 | 处理 |
|---|---|---|
| `MQTT 不可用，已降级为本地快照` | EMQX 连接失败 | 检查 1883 端口与 ACL；服务已自动降级，可继续运行 |
| `EMQX 已连接` | MQTT 链路恢复 | 无需处理 |
| `报文解析失败` | 上游报文 JSON 非法 | 检查仿真器版本与字段 |
| `快照生成失败` | 定时任务异常 | 看堆栈，检查内存与 `RuntimeState` |
| `初始化失败：` | 前端启动异常 | 浏览器控制台查看堆栈，多为 WebGL 或配置问题 |

统一响应中的 `traceId` 可用于串联前端请求与后端日志（P1 接入日志采集后端到端）。

## 4. 健康检查端点

| 端点 | 用途 |
|---|---|
| `/q/health` | 存活与依赖连通性（PG / Redis / TDengine / MinIO / EMQX） |

```bash
curl -s http://localhost:8082/q/health | jq

```

## 5. 备份与恢复

### 5.1 PostgreSQL

```bash
# 备份
docker exec bdt-postgres pg_dump -U bridge -Fc bridge > backup/bridge_$(date +%F).dump
# 恢复（先停服务，避免写入）
docker compose stop svc-bridge svc-shm
docker exec -i bdt-postgres pg_restore -U bridge -d bridge --clean < backup/bridge_2026-11-06.dump
docker compose start svc-bridge svc-shm
```

### 5.2 Redis / TDengine / MinIO

```bash
docker exec bdt-redis redis-cli SAVE                 # 生成 dump.rdb
docker exec bdt-tdengine taosdump -o backup/taos    # 时序数据导出
docker exec bdt-minio mc mirror local/bridge-models backup/minio/bridge-models
```

Redis 为实时缓存（TTL 5s），丢失可接受；TDengine 与 MinIO 为历史与模型资产，需按周备份。

### 5.3 配置与卷

```bash
tar czf backup/config_$(date +%F).tgz .env docker-compose.yml deploy/
docker run --rm -v bridge-digital-twin_pg-data:/v -v "$PWD/backup":/b alpine tar czf /b/pg-data.tgz -C /v .
```

恢复后按 [02-项目启动运行指南](02-项目启动运行指南.md) 第 7 节执行启动自检。

## 6. 监控指标与建议告警规则

| 指标 | 来源 | 建议阈值 | 动作 |
|---|---|---|---|
| `http_server_requests_seconds` p95 | 两个服务 `/q/metrics` | > 1s 持续 5min | 查慢查询与 JVM |
| JVM 堆使用率 | Micrometer | > 80% 持续 10min | 检查容器内存上限（512M）并扩容 |
| MQTT 客户端数 | EMQX Dashboard | 低于预期客户端数 | 检查断连与 ACL |
| `rejected` 增长率 | `/system/stats` | 5min 内 > 10% | 检查上游传感器/仿真器报文 |
| ACTIVE 告警数 | `/alarms?status=ACTIVE` | 突增 | 排查是否阈值配置错误或真实异常 |
| 前端 FPS | 顶栏显示 | < 20 持续 | 已自动关闭后处理；检查 GPU 与视口分辨率 |
| 容器重启次数 | `docker compose ps` | > 0 | 查日志与 OOM |

Grafana 看板配置在 `deploy/grafana/provisioning/`，Prometheus 抓取任务在 `deploy/prometheus/prometheus.yml`。

## 7. 容量与性能调优

| 项 | 默认 | 调优方向 |
|---|---|---|
| 前端像素比 | 受设备限制 | 低性能设备降 `renderer.setPixelRatio`，关闭 Bloom |
| 后处理 | Bloom + ACES | FPS < 20 自动关闭（`Viewport`） |
| 车辆实例 | 36 台 / 上限 300 | 超过阈值自动降级为简化几何 |
| 快照周期 | 2000ms（`bdt.snapshot.interval.ms`） | 增大可降低带宽，减小可提高实时性 |
| 历史缓冲 | 每测点 3000 条（`RuntimeState`） | cluster 模式交给 TDengine，`KEEP 365` |
| Redis | 220MB / allkeys-lru | 按桥梁数与测点数扩容 |
| 容器内存 | PG 1G / TDengine 1G / 服务各 512M | 4C/8G 单机上限约 5G |

## 8. 故障处置矩阵

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 页面白屏 | WebGL2 不可用、`live` 模式初始化异常 | 更换浏览器/开启硬件加速；看控制台；切 `mock` 验证 |
| 面板只有标题无数值 | 面板数据未刷新（曾出现于初版） | 确认 `createPanel` 首次 `update` 会渲染行结构；刷新页面 |
| 拉索/桥体不可见 | 相机处于幕四桥底视角 | 顶栏视点下拉切「全景鸟瞰」 |
| 数值长期不变 | 数据源停止推送 | 查仿真器进程、`/system/stats`、MQTT 客户端 |
| 告警不触发 | 未达 3 次防抖 / 阈值未超 | 点「模拟告警」验证；查 `bdt.alarm.debounce.up` |
| 告警一直不恢复 | 上游持续超限 | 检查 `BridgeResponseModel.injectOverlimit` 是否复位 |
| MQTT 反复断连 | 端口占用 / ACL / 客户端 ID 冲突 | 检查 1883、8083；查看 EMQX Dashboard |
| 后端启动即退出 | 端口被占用 / JDK 非 17 | `netstat -ano \| findstr 8081`；`java -version` |
| Docker 首次启动无种子数据 | 数据卷非空，初始化脚本未执行 | 备份后 `docker compose down -v` 重新初始化 |
| 接口 404 | Nginx 分流到错误服务 | 对照 [04-接口文档](../02-开发文档/04-接口文档.md) §2 检查路由 |
| 前端跨域报错 | 直连后端未走代理 | 用 Vite dev 代理或 Nginx；服务已开启 CORS |
| Compose 内存不足 | 多容器同时启动 | 分批 `up -d`，或提高宿主机内存 |

更多问答见 [08-常见问题解答](08-常见问题解答.md)。

## 9. 升级与回滚

1. 备份（§5）并记录当前镜像/提交版本。
2. 在测试环境执行 [06-测试与验收清单](../04-测试与规范/06-测试与验收清单.md) 第 8 节回归顺序。
3. 前端：`npm run build` 产出 `dist`，Compose 中 `frontend-build` 把产物复制到 `frontend-dist` 卷，重启 `nginx`。
4. 后端：`mvn -DskipTests package` 后重建镜像 `docker compose up -d --build svc-bridge svc-shm`。
5. 数据库变更：新增迁移脚本（不要修改已执行过的 `01_schema.sql`），先在新环境验证；回滚时用备份恢复。
6. 回滚：`docker compose down` → 恢复上一版镜像/产物与备份 → `docker compose up -d` → 自检。

## 10. 安全与账号

| 项 | 默认 | 生产建议 |
|---|---|---|
| PG / MinIO / EMQX / Grafana 口令 | `.env.example` 中的明文示例 | 全部更换，密钥托管 |
| EMQX 匿名访问 | `true`（便于本地联调） | 关闭，按客户端分配账号，收紧 `acl.conf` |
| Nginx CORS | `*` | 收敛到具体域名，启用 HTTPS / WSS |
| PG / Redis 绑定 | `127.0.0.1` | 保持，仅经内网访问 |
| `sys_user.password` | 示例字段 | P1 换加盐哈希并接入鉴权 |
