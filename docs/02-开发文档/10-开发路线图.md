## 1. 阶段总览

| 阶段 | 目标 | 状态 | 建议周期 |
|---|---|---|---|
| **P0 可运行原型** | 一个页面 + 五幕动画 + 三链路 + 双服务 + 全套部署配置，无中间件也能演示 | **已交付** | — |
| **P1 生产化替换** | 把「程序化几何 / 内存仓储 / 匿名 MQTT」替换为真实资产与持久化 | 规划 | 4~6 周 |

## 3. P1 · 生产化替换（建议 4~6 周）

### 3.1 数据层落地

| # | 任务 | 具体替换点 | 验收 |
|---|---|---|---|
| P1-1 | 桥梁/构件读 PG | `backend/svc-bridge/.../RuntimeStore.java` → `JdbcRepository`，`bdt.storage=cluster` | `/bootstrap` 与 DDL 字段一一对应 |
| P1-2 | 实时值写 Redis | `RuntimeState.realtime` → `realtime:shm:*`（TTL 5s） | 重启服务后最新值可从缓存恢复 |
| P1-3 | 时序写 TDengine | `RuntimeState.history` 环形队列 → `shm_metric` 批量写（10s 一批） | `taos` 可查到 150 点数据 |
| P1-4 | 历史查询走 TDengine | `RuntimeState.series/statistics` → `INTERVAL()` 聚合 SQL | 24h 查询 p95 < 500ms |
| P1-5 | 模型与截图入 MinIO | `POST /models/upload` 从登记元数据改为真实上传 + 预签名 URL | 上传后 `publicUrl` 可下载 |

### 3.2 模型与安全

| # | 任务 | 说明 | 验收 |
|---|---|---|---|
| P1-6 | 三维资产绑定 | 已实现 `AssetLoader` + 下载脚本；按核查清单用 CC0 车辆/护栏/道闸 GLB 接管，缺失时程序化兜底 | `frontend/src/three/AssetLoader.ts` |
| P1-7 | Draco 压缩 + LOD | `frontend/src/three/AssetLoader.ts` 接入 `DRACOLoader`，按距离切 LOD | 首屏加载 ≤ 3s |
| P1-8 | 保留 `clipExempt` 语义 | GLB 加载后按 `brg_component.clip_exempt` 决定是否挂 ClippingPlane | 剖切只切外壳 |
| P1-9 | 登录鉴权 | `sys_user` 密码改加盐哈希，接入 JWT / OIDC | 未登录不可写接口 |
| P1-10 | MQTT 认证与 ACL | 关闭 `EMQX_ALLOW_ANONYMOUS`，按客户端分配账号，收紧 `deploy/emqx/acl.conf` | 匿名连接被拒 |

### 3.3 可观测性与质量

| # | 任务 | 验收 |
|---|---|---|
| P1-11 | Grafana 业务看板：FPS、告警速率、车流、清洗拒绝率 | 看板可复现故障 |
| P1-12 | 日志采集 + `traceId` 端到端串联 | 一次请求可检索全链路日志 |
| P1-13 | 自动化测试：Vitest（前端单元）、JUnit（服务）、端到端脚本 | CI 中执行回归清单 |

| P1-15 | 历史数据保留与降采样任务 | `KEEP 365` 生效，滚动归档 |

**P1 完成定义**：关闭内存模式后，全栈在 Docker Compose 下运行 24h 无数据丢失，`/q/health` 中 5 个组件全 UP，回归清单全绿。

## 4. P2 · 扩展能力（建议 8~12 周）

| 方向 | 任务 |
|---|---|
| 多桥 | 桥梁切换与桥群总览；所有编码、MQTT 主题、缓存 Key 已带 `bridgeCode`，扩展成本较低 |
| 养护业务 | 巡检工单、养护计划、报表导出、缺陷闭环 |
| 真实接入 | 多协议传感器网关（Modbus / OPC-UA / HTTP），替换 SimPy 数据源 |
| 算法 | 车流—结构耦合工况库、离线有限元结果回放、缺陷图像识别、趋势预测 |
| 交付形态 | 4K 大屏与多屏联动、移动端巡检 App、私有化离线部署包 |
| 平台化 | 多租户、权限分级、审计中心 |

## 5. 关键依赖与风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 缺少 Blender 源文件 | P1-6 无法直接产出精模 | 先用程序化几何导出 GLB 过渡；保留三套模型编码契约 |
| TDengine 与 PG 双写一致性 | 实时值与档案不一致 | 明确职责：PG 只存元数据，时序与实时值不写 PG |
| MQTT QoS 1 重传导致重复计数 | 防抖计数被放大 | 以 `ts + pointCode` 去重后再累计 streak |
| GLB 体积过大 | 首屏超过 3s | Draco + LOD + 分帧加载；骨架态先用线框 |
| 150 测点 × 2s 写入压力 | 时序库写入瓶颈 | 批量提交（10s 一批）+ 超级表标签分区 |
| 前端后处理开销 | 低配设备帧率低 | 已有 FPS < 20 自动降级；可进一步下调像素比 |
| 多桥引入后编码冲突 | 测点/构件编码重复 | 所有唯一索引均带 `bridge_code` 或全局唯一业务码 |

## 6. 扩展指引

### 6.1 替换桥梁几何来源

1. 按 `scn_model` 上传 9 个 GLB 到 MinIO bucket `bridge-models`；
2. `bootstrap.models[].publicUrl` 指向可访问地址；
3. 在 `frontend/src/three/BridgeBuilder.ts` 的 `build()` 中按 `modelSolidCode / modelSkeletonCode / modelInnerCode` 加载并替换对应 Group；
4. 保持 `setDrawRange`（骨架生长）、`clipExempt`（剖切豁免）、`shell` 实例（热力着色）三个扩展点不变；
5. 回归 [06-测试与验收清单](../04-测试与规范/06-测试与验收清单.md) 的 V-11 与 F-01/F-06。

### 6.2 切换持久化实现

1. `application.properties` 设 `bdt.storage=cluster`；
2. 实现 `RuntimeStore` / `RuntimeState` 中标注「可切 cluster」的方法；
3. REST 契约与 `frontend/src/types/index.ts` **保持不变**，前端无需修改；
4. 用 `/system/stats` 与 `/q/health` 验证写入链路；
5. 按 [07-运维手册](../03-部署与运维/07-运维手册.md) §5 做首次备份。

### 6.3 新增测点 / 新增一幕

- 测点：在 `deploy/postgres/init/02_seed.sql`、`backend/*/SeedData*.java`、`frontend/src/config/index.ts` 三处同构新增；`shm_point.group_code` 需在 CHECK 枚举内；TDengine 建对应子表。
- 新幕：在 `brg_anim_stage` / `SeedData.animStages()` / 前端 `ACTS` 定义时间区间与关键帧，在 `frontend/src/three/acts.ts` 增加 `applyActN()`，并在 HUD `HUD_ACTS` 补节点。

> 三处同构是本项目的核心约束：**改数据必须同时更新 DDL 种子、后端 Seed、前端 config**，否则 live 与 mock 模式会出现字段差异。

## 7. 明确不做（需求文档 1.4）

- 实时有限元求解（仅离线结果回放）；
- 真实传感器硬件采购与安装；
- 多桥集群的实时同步（P2 的多桥为管理态切换）；
- 视频流 AI 事件检测。
