## 1. 项目定位

一个页面讲清一座桥的三件事：**左栏「这座桥是什么」、中间「它长什么样、里面是什么样」、右栏「它现在怎么样」**。
打开页面后自动播放 12.5 秒五幕动画，随后进入稳态巡检；全过程可暂停、重播、倍速、跳幕，可切换到三种数据视图，也可自由操作相机。

设计基准 1920×1080，三栏宽度 320 / flex / 340，顶栏 64px，底部 HUD 88px。

## 3. 五幕动画（总时长 12.5s）

统一由 `frontend/src/three/Timeline.ts` 提供归一化进度，`acts.ts` 计算每幕的几何/材质/相机状态，`Viewport.ts` 每帧应用。

| 幕 | 时段 | 画面动作 | 相机 | 主要实现 |
|---|---|---|---|---|
| 幕一 骨架生成 | 0 ~ 4.5s | 桩基 → 承台 → 墩 → 塔 → 主梁骨架 → 拉索按施工顺序出现；线框逐步转实体；塔顶白闪 + Bloom | 远景 (600,120,600) 推近到 (420,180,520) | `BridgeBuilder`、`setDrawRange`、`applyAct1` |
| 幕二 桥面合龙 | 4.5 ~ 7.5s | 42 个箱梁节段从两侧向跨中合龙，B-21/B-22 最后落位；桥面铺装、护栏、支座显现 | (420,180,520) → (260,110,360) | `applyAct2`、`CameraDirector` |
| 幕三 车辆加载 | 7.5 ~ 9.5s | 72 台车在 12 条车道渐入，拖尾点亮；右栏车流数值开始滚动 | → (-380,62,2) 桥面平视 | `TrafficEngine`、`applyAct3` |
| 幕四 结构透视 | 9.5 ~ 12.5s | 相机钻入桥底；外壳被剖切（`ClippingPlane` 只作用于外壳，塔/车/地面豁免）；露出四室箱梁、横隔板、加劲肋与青色描边；橙色传感器与虚线渐显；右栏切「内部透视」 | (-160,24,180) → (60,8,120) 桥底仰视 | `ClippingController`、`SensorLayer`、`applyAct4` |
| 幕五 稳态巡检 | 12.5s 起 | 以断口为中心 ±12° 缓慢环绕（周期 24s）+ 轻微呼吸推拉；传感器按数据三态刷新；监测数据持续驱动 | 环绕关键帧 | `applyAct5`、`HeatMapper` |

播放控制：空格播放/暂停、`R` 重播、时间轴节点点击跳幕、倍速循环 0.5x / 1x / 1.5x / 2x。
用户拖拽或滚轮操作相机后，`CameraDirector` 暂停自动运镜 8 秒，避免抢镜头。

## 4. 功能模块逐项

### 4.1 BRG 桥梁与构件管理

- 桥梁档案：CRUD + 首屏聚合 `bootstrap`（一次性返回档案、构件、拉索、节段、车道、视点、剖切方案、五幕、模型、测点、巡检、仿真方案、指标）。
- 三级构件树：顶层 12 类（塔、墩、承台、主梁、内部结构、铺装、护栏、支座、传感器等）+ 42 节段 + 72 拉索；复选框显隐、点击名称相机定位、异常构件红点。
- 几何台账：72 根拉索（双塔双索面，锚点按塔高递减）、42 个箱梁节段（每 20 m，B-21/B-22 为合龙段）、12 条车道（上下行各 6，offset ±1.75 ~ ±19.25 m）。
- 视点与剖切：6 个预设视点、2 个剖切方案（沿桥轴 / 横向），法向、裁剪距离、内部件显隐、描边颜色均可配置。
- 实现位置：`backend/svc-bridge/.../BridgeResource.java`、`SeedData.java`、`frontend/src/config/index.ts`、`frontend/src/panels/ComponentTree.ts`。

### 4.2 VIS 三维可视化

- 分层建模：程序化生成塔、墩、承台、桩基、42 节段外壳、四室箱梁内部、72 拉索、支座、护栏、桥面、水面与城市天际线，坐标约定 **X 沿桥轴、Y 高度、Z 横向、跨中为原点**。
- 材质：Bloom 选择性辉光（仅拉索/传感器/描边）、ACES Filmic 色调映射、蓝图线框材质、雾与水波渐变。
- 剖切：`renderer.localClippingEnabled` + `Plane` 只挂到外壳材质；`clipExempt` 构件不受影响；剖面边缘青色发光线。
- 拾取：`Raycaster` 命中构件/车辆/传感器 → `OutlinePass` 高亮 → Store 事件 → 构件档案卡或车辆信息卡，并联动构件树与相机。
- 热力：`HeatMapper` 按测点等级对 42 节段实例着色（青→黄→红），告警态红色脉冲；拉索整体发光色随之切换。
- 性能：帧率连续低于 20 FPS 自动关闭后处理；车辆与传感器用 `InstancedMesh`；`setDrawRange` 实现生长而不重建几何。
- 结构生长缩略图：2D 彩色点云（#00E5FF → #7BFFCF → #FFD166 → #FF6B6B），点击重播。
- 实现位置：`frontend/src/three/` 全部 12 个模块。

### 4.3 TRA 车流仿真

- SimPy 按车道泊松到达，85% 小车 / 15% 货车，车速正态 N(58, 9) 截断到 40~80 km/h，在途目标 `(density/62)*36`。
- 每秒只发稀疏状态（`vid / lane / t / speed / type` + `stat` + `removed`），前端用 `CatmullRomCurve3.getPointAt(t)` 补帧到 60 FPS，带宽降低约 90%。
- `InstancedMesh` 分小车、货车、灯带、拖尾 4 类，车辆总 DrawCall ≤ 4；超过 300 台自动降级。
- 密度滑块 0~100%（含左右进度条与 ±5 按钮），1 秒内生效；点击车辆显示车牌/车型/载重/车速/车道/驶入时间。
- 实现位置：`simulator/traffic_sim.py`、`frontend/src/three/TrafficEngine.ts`、`frontend/src/panels/Overlays.ts`。

### 4.4 SHM 结构健康监测

- 9 类测点字典、150 个测点：72 索力 + 42 应变 + 36 环境/变形/支座/裂缝；每点含构件绑定、双阈值、3D 位置、分组与排序号。
- 清洗：校验 `pointCode` 存在、`value` 为有限数、时间偏差 ≤ 5 分钟，脏数据丢弃并计数（`/api/v1/system/stats` 可查）。
- 聚合：结构应力取最大、索力取最大（MN→kN）、挠度取跨中、温度/风速/频率/阻尼取均值；健康评分随活动告警降级 96 → 88。
- 传感器三态：NORMAL 橙色、WARN 黄色脉冲、ALARM 红色脉冲，索线发光同步；整桥 2s 快照推送。
- 历史：按时间桶降采样（AVG / MAX / MIN）、区间统计 count/max/min/avg/P95/exceedCount、指定时刻快照；历史不足 24h 用平滑序列回填，回放无空洞。
- 实现位置：`backend/svc-shm/.../RuntimeState.java`、`MqttGateway.java`、`simulator/shm_sim.py`、`bridge_model.py`。

### 4.5 ALM 告警管理

- 双阈值：应力 `warn_max=55 MPa / alarm_max=70 MPa`；索力 `warn_max=1.350 MN / alarm_max=1.400 MN`（C-03 为 1.360 MN）。
- **连续 3 次超限**才触发（防抖），同一测点已有活动告警不重复弹窗；**连续 3 次正常**自动恢复并推送 `alarm/bridge/recover`。
- 状态机：`ACTIVE → CONFIRMED / IGNORED / RECOVERED`；弹窗可确认或忽略，右栏列表展示最近 5 条，点击定位构件。
- 触发后联动：红色脉冲、索线转红、健康等级 A→B、eventCount +1、构件树红点。
- 顶栏「模拟告警」按钮现场演示完整生命周期。详见 [07-告警生命周期图](../01-架构与设计图/07-告警生命周期图.svg)。

### 4.6 WEB 前端交互

- 单一状态源 `Store` + 面板到应用层的 `AppActions` 契约，面板之间不互相调用。
- 数值 0.6s 滚动（千分位、中断时从当前显示值续接）、加载遮罩 8→100%、toast 提示。
- 轨道控制器 + WASD/QE 平移、视点下拉、全屏、3D 视口截图、构件树显隐、时间轴跳幕。
- 响应式降级：小屏自动缩窄三栏、降低像素比与后处理强度。

### 4.7 RPT 统计与回放

- `GET /history/series` 返回 `HistorySeries[]`（`[ts, value]` 序列），前端 `sparkline` 绘制 24h 迷你折线图。
- `GET /history/statistics` 返回最大/最小/均值/P95/超限次数；`GET /history/snapshot?t=` 返回指定时刻快照。
- 巡检记录（扫描完成 94%、缺陷 2 处、重点区域 箱梁 B-03、下次巡检 2026-11-12）驱动 V3 右栏。

### 4.8 SYS 系统管理

- 统一响应 `{code, msg, data, traceId}`，`code=0` 成功；`/q/health` 聚合 PG / Redis / TDengine / MinIO / EMQX 连通性；`/q/metrics` 暴露指标。
- `sys_user / sys_config / sys_oper_log` 三表；服务内记录模型上传、桥梁/构件变更、仿真启停、动画重播等操作日志。
- 双数据源自动降级：`live` 模式下 REST 或 MQTT 不可达时切 `mock`，顶栏提示，不白屏。

## 6. 数据源与降级矩阵

| 模式 | 首屏 | 实时指标/告警 | 车流 | 历史 | 触发条件 |
|---|---|---|---|---|---|
| `mock`（默认） | 本地 `buildMockBootstrap()` | `mockSource` 2s 推送 | `mockSource` 1s 稀疏状态 | 本地 24h 序列 | `VITE_DATA_MODE=mock` |
| `live` | REST `bootstrap` | MQTT `realtime/bridge/*`、`alarm/*` | MQTT `traffic/vehicle/*` | REST `/history/*` | `VITE_DATA_MODE=live` |
| 降级 | bootstrap 失败 → 本地种子 | MQTT 断连 3 次 → mockSource | 同上 | 查询失败 → 本地序列 | 自动，toast 提示 |

后端同样有降级：EMQX 不可达时 `svc-shm` 用 `tickLocalSimulation()` 维持 2s 快照，`/q/health` 中相应组件显示 DOWN 但服务仍 UP。
