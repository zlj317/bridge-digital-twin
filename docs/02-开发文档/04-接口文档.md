## 1. 通用约定

| 项 | 约定 |
|---|---|
| 基地址 | 本机直连 `http://localhost:8081`（svc-bridge）/ `http://localhost:8082`（svc-shm）；Docker 经网关统一为 `http://localhost/api/v1` |
| 版本前缀 | `/api/v1` |
| 内容类型 | 请求/响应 `application/json; charset=UTF-8` |
| 统一响应 | `{ "code": 0, "msg": "ok", "data": ..., "traceId": "8位随机" }`，`code=0` 成功，非 0 为业务失败 |
| 时间 | 毫秒时间戳（`ts`）；告警时间用 ISO-8601 字符串 |
| 编码 | 全部业务码使用大写英文 + 连字符，如 `BR-DEMO-01` / `PTS-C-01` |
| CORS | Nginx 与两个 Quarkus 服务均允许跨域（开发环境 `*`） |
| 分页 | `/bridges?page=1&size=20` 返回 `{list,total,page,size}` |
| 幂等 | 桥梁/构件的 PUT 为 upsert；告警 confirm / ignore 重复调用返回当前状态 |

前端类型契约定义在 `frontend/src/types/index.ts`，REST 客户端在 `frontend/src/api/client.ts`。

## 2. Nginx 分流规则

| 请求 | 目标 |
|---|---|
| `/`、静态资源 | `frontend-dist` 卷 |
| `/api/v1/bridges/{code}/(metrics\|health\|inspections)` | svc-shm:8082（正则 location 优先） |
| `/api/v1/points*`、`/api/v1/alarms*`、`/api/v1/history/*`、`/api/v1/sensor/*` | svc-shm:8082 |
| 其余 `/api/v1/*` | svc-bridge:8081 |
| `/mqtt` | EMQX:8083（WebSocket Upgrade） |
| `/q/health` | svc-shm:8082 |
| 其余 `/q/*` | svc-bridge:8081 |

## 3. svc-bridge 接口（:8081，26 个）

### 3.1 桥梁与构件

| 方法 | 路径 | 说明 | 主要响应 |
|---|---|---|---|
| GET | `/api/v1/bridges?page=&size=` | 桥梁列表 | `{list,total,page,size}` |
| GET | `/api/v1/bridges/{code}` | 桥梁详情 | `Bridge` |
| POST | `/api/v1/bridges` | 新建桥梁 | `Bridge`（body 缺 `bridgeCode` 时用默认编码） |
| PUT | `/api/v1/bridges/{code}` | 更新/新增（upsert） | `Bridge` |
| DELETE | `/api/v1/bridges/{code}` | 删除 | `{deleted:true/false}` |
| GET | `/api/v1/bridges/{code}/bootstrap` | **首屏整包** | `Bootstrap`（14 个字段，见 §6.1） |
| GET | `/api/v1/bridges/{code}/components?type=` | 构件树，可按 `compType` 过滤 | `BridgeComponent[]` |
| GET | `/api/v1/components/{compCode}` | 单个构件 | `BridgeComponent` |
| POST | `/api/v1/components` | 新建构件 | `BridgeComponent` |
| PUT | `/api/v1/components/{code}` | 更新构件 | `BridgeComponent` |
| GET | `/api/v1/bridges/{code}/cables?towerSide=L\|R` | 72 根拉索 | `Cable[]` |
| GET | `/api/v1/bridges/{code}/segments` | 42 个箱梁节段 | `GirderSegment[]` |
| GET | `/api/v1/bridges/{code}/lanes` | 12 条车道曲线 | `Lane[]` |
| GET | `/api/v1/bridges/{code}/viewpoints` | 6 个视点 | `Viewpoint[]` |
| GET | `/api/v1/bridges/{code}/clip-plans` | 2 个剖切方案 | `ClipPlan[]` |
| GET | `/api/v1/bridges/{code}/anim-stages` | 五幕动画配置 | `AnimStage[]` |
| GET | `/api/v1/bridges/{code}/models` | 模型资源清单 | `ModelResource[]` |
| POST | `/api/v1/models/upload` | GLB 上传登记（当前返回对象键与 URL 占位） | `ModelResource` |
| GET | `/api/v1/system/oper-logs` | 操作日志（最近 200 条） | `OperLog[]` |

### 3.2 仿真、车流与动画

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/sim/plans` | 仿真方案列表 |
| POST | `/api/v1/sim/plans/{code}/start` | 启动（status → RUNNING） |
| POST | `/api/v1/sim/plans/{code}/stop` | 停止（status → STOPPED） |
| PUT | `/api/v1/sim/plans/{code}/density?density=80` | 设置密度 0~100，同步刷新车流统计 |
| GET | `/api/v1/traffic/{code}/stat` | 车流统计 `{vehicleCount,avgSpeed,occupancy,eventCount}` |
| GET | `/api/v1/anim/{code}/stages` | 五幕分幕配置 |
| POST | `/api/v1/anim/{code}/replay` | 触发重播（记录日志） |

## 4. svc-shm 接口（:8082，15 个）

| 方法 | 路径 | 说明 | 主要响应 |
|---|---|---|---|
| GET | `/api/v1/bridges/{code}/metrics` | 聚合指标 | `BridgeMetrics` |
| GET | `/api/v1/points?bridgeCode=&groupCode=` | 测点列表（150 个，可按分组过滤） | `ShmPoint[]` |
| POST | `/api/v1/points/realtime` | 批量写入实时值（数组或 `{points:[...]}`） | `{accepted,received}` |
| GET | `/api/v1/points/{pointCode}/realtime` | 单测点实时值 | `RealtimePoint` |
| GET | `/api/v1/alarms?bridgeCode=&level=&status=` | 告警列表 | `{list,total}` |
| POST | `/api/v1/alarms/{alarmCode}/confirm` | 确认告警 | `Alarm(status=CONFIRMED)` |
| POST | `/api/v1/alarms/{alarmCode}/ignore` | 忽略告警 | `Alarm(status=IGNORED)` |
| GET | `/api/v1/bridges/{code}/health` | 健康评分与活动告警数 | `{score,grade,activeAlarms,updatedAt}` |
| GET | `/api/v1/bridges/{code}/inspections` | 巡检与缺陷记录 | `Inspection[]` |
| GET | `/api/v1/history/series?points=&start=&end=&interval=&aggr=` | 降采样时序 | `HistorySeries[]` |
| GET | `/api/v1/history/statistics?point=&start=&end=` | 区间统计 | `HistoryStatistics` |
| GET | `/api/v1/history/snapshot?t=` | 指定时刻快照 | `{t,metrics,points,traffic}` |
| POST | `/api/v1/sensor/ingest` | 原始报文清洗入口（无 MQTT 时可直接 HTTP 上报） | `{accepted,received}` |
| GET | `/api/v1/system/stats` | 清洗统计 `{accepted,rejected,points,historyRows}` | `Stats` |
| GET | `/api/v1/snapshot` | 立即生成并发布整桥快照 | `Snapshot` |

查询参数说明：

| 参数 | 默认 | 说明 |
|---|---|---|
| `points` | `PTS-C-01` | 逗号分隔测点编码，如 `PTS-C-01,PTS-C-02` |
| `point` | `PTS-C-01` | `/statistics` 的单测点编码 |
| `start` / `end` | 最近 24h | 毫秒时间戳；`end <= start` 时自动补 1h |
| `interval` | `10s` | 支持 `10s` / `1m` / `6m` / `1h`，最小 1s |
| `aggr` | `AVG` | `AVG` / `MAX` / `MIN` |
| `level` / `status` | 空 | 告警过滤：`WARN\|ALARM\|SERIOUS`、`ACTIVE\|CONFIRMED\|IGNORED\|RECOVERED` |

## 5. 健康检查与指标

| 路径 | 服务 | 说明 |
|---|---|---|
| `/q/health` | 两个服务 | SmallRye Health，`status: UP`；`data` 中给出 postgres / redis / tdengine / minio / emqx 的 UP/DOWN |
| `/q/metrics` | 两个服务 | Micrometer / Prometheus 文本格式 |

> 健康检查把外部组件连通性作为 `data` 输出而非判定服务 DOWN，因此中间件未启动时服务仍可用，便于渐进式联调。

### 6.6 清洗入口

```bash
curl -X POST http://localhost:8082/api/v1/sensor/ingest \
  -H "Content-Type: application/json" \
  -d '{"points":[{"pointCode":"PTS-C-01","value":1.291,"ts":1793931973632},{"pointCode":"BAD","value":"x"}]}'
# {"code":0,"data":{"accepted":1,"received":2},"traceId":"…"}
```

非法测点、非数值、NaN/Infinity、时间偏差 > 5 分钟的样本被丢弃，`rejected` 累加。

## 7. 数据契约摘要（TypeScript）

```ts
type Vec3 = { x: number; y: number; z: number };
type PointLevel = 'NORMAL' | 'WARN' | 'ALARM';
type RealtimePoint = { pointCode: string; compCode: string; value: number;
                       unit: string; ts: number; level: PointLevel };
type VehicleState = { vid: string; lane: string; t: number; speed: number;
                       type: 'CAR' | 'TRUCK' };
type Alarm = { alarmCode: string; compCode: string; pointCode: string;
               alarmLevel: 'WARN' | 'ALARM' | 'SERIOUS';
               title: string; content: string; alarmValue: number;
               thresholdValue: number; unit: string;
               status: 'ACTIVE' | 'CONFIRMED' | 'IGNORED' | 'RECOVERED';
               triggerTime: string };
type HistorySeries = { pointCode: string; unit: string; points: [number, number][] };
type HistoryStatistics = { pointCode: string; count: number; max: number; min: number;
                           avg: number; p95: number; exceedCount: number };
```

完整定义见 `frontend/src/types/index.ts`；前端 `mockSource` 与后端 `SeedData` 使用同构字段，切换 `live/mock` 模式无需改面板。

## 8. 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `code=1, msg=桥梁不存在: XXX` | 编码错误或该桥梁已删除 | 使用 `BR-DEMO-01` 或先 POST 创建 |
| `code=1, msg=测点不存在: XXX` | 测点编码不在 150 个之内 | 查 `GET /points` 获取合法编码 |
| 404 | 路径被 Nginx 分流到错误服务 | 对照 §2 检查路由；本机直连 8081/8082 验证 |
| 跨域错误 | 浏览器直连后端且未走代理 | 用 Vite dev 代理或 Nginx；服务已开启 CORS |
| 历史为空 | 服务刚启动、内存历史不足 | 稍等 2s 快照；接口会用平滑序列回填 |

更多排查见 [08-常见问题解答](../03-部署与运维/08-常见问题解答.md)。
