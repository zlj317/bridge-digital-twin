## 1. 业务与领域术语

| 术语 | 英文 / 缩写 | 含义（本项目语境） |
|---|---|---|
| 数字孪生 | Digital Twin | 以三维模型 + 实时数据映射物理桥梁，实现可视化、监测与回放 |
| 桥梁档案 | Bridge Profile | `brg_bridge` 中的主数据：塔高 216 m、主跨 480 m、全桥 840 m、设计荷载 55 t 等 |
| 构件树 | Component Tree | 三级结构：顶层 12 类 → 42 个箱梁节段 / 72 根拉索；支持显隐与定位 |
| 双塔双索面 | Double-tower, double cable plane | 两座桥塔 × 两个索面 × 每面 18 根 = 72 根拉索 |
| 合龙段 | Closure Segment | B-21 / B-22，幕二最后落位的两节箱梁 |
| 五幕动画 | Five-act Timeline | 骨架生成 → 桥面合龙 → 车辆加载 → 结构透视 → 稳态巡检，总 12.5s |
| 稳态巡检 | Steady Inspection | 幕五起以断口为中心 ±12° 缓慢环绕（周期 24s）+ 呼吸推拉 |
| 预设视点 | Viewpoint Preset | 6 个相机位：全景鸟瞰、桥面平视、桥底剖切、塔柱特写、等轴测、桥侧远景 |
| 剖切方案 | Clip Plan | 法向 + 距离 + 内部件显隐 + 描边色；沿桥轴 / 横向两种 |
| 内部透视 | Inner Perspective | 剖切后显示四室箱梁、横隔板、加劲肋、支座与传感器的视图（图 3） |
| 热力色阶 | Heat Scale | 索力 1.40 MN 红 → 1.36 橙 → 1.32 紫 → 1.28 青 → 1.24 蓝，5 级 |
| 索力 | Cable Force | 单位 MN（后端换算为 kN 供左栏显示），设计 1.280、预警 1.350、告警 1.400 |
| 挠度 | Deflection | 主梁竖向变形，跨中约 0.86 m |
| 结构应力 | Structural Stress | 主梁应变测点最大值，约 42 MPa，预警 55 / 告警 70 MPa |
| 疲劳指数 | Fatigue Index | 综合指标，当前固定 38 |
| 健康评分 / 等级 | Health Score / Grade | 正常 96 分 / A 级，存在活动告警时 88 分 / B 级 |
| 双阈值 | Dual Threshold | `warn_max` 预警阈值与 `alarm_max` 告警阈值 |
| 防抖 | Debounce | 连续 3 次超限才触发、连续 3 次正常才恢复，抑制抖动误报 |
| 活动告警 | Active Alarm | `status=ACTIVE`，同一测点不重复弹窗 |
| 缺陷台账 | Defect Ledger | `shm_inspection`，扫描完成 94%、缺陷 2 处、重点区域 箱梁 B-03 |
| 稀疏状态 | Sparse State | 车流每秒只发 `t + speed` 等少量字段，前端本地补帧 |
| 补帧 | Interpolation | 用 `CatmullRomCurve3.getPointAt(t)` 把 1s 报文插值为 60 FPS 连续运动 |
| 降采样 | Downsampling | 按 `interval` 时间桶聚合 AVG / MAX / MIN，减少历史查询点数 |
| P95 | 95th Percentile | 区间统计中的 95 分位值 |
| 首屏整包 | Bootstrap | 一次 REST 返回 14 类首屏数据，避免多次往返 |
| 稳态数据源 | mock / live | `mock` 内置仿真、`live` REST + MQTT；失败自动降级 |

## 2. 前端与三维渲染术语

| 术语 | 含义 |
|---|---|
| Three.js r168 | 本项目 WebGL 渲染库 |
| WebGL2 | 浏览器 GPU 渲染接口，页面必需 |
| Scene / Mesh / Material | 场景、网格、材质 |
| InstancedMesh | 一次 DrawCall 渲染大量同构对象（车辆、传感器、节段） |
| DrawCall | GPU 绘制调用次数；车辆层设计为 ≤ 4 |
| `setDrawRange` | 只显示几何体前 N 个索引，用于骨架逐步生长 |
| LOD | Level of Detail，按距离加载不同精度模型（P1） |
| GLB / Draco | 二进制 glTF 模型 / Google 几何压缩；模型资源表中有登记 |
| Bloom | 选择性辉光后处理，仅作用于拉索、传感器、描边 |
| ACES Filmic | ACES 电影级色调映射 |
| OutlinePass | 拾取命中后的轮廓高亮 |
| Raycaster | 射线拾取，判断点击命中哪个构件/车辆/传感器 |
| ClippingPlane / `localClippingEnabled` | 局部剖切平面；只挂到外壳材质实现「只切外壳」 |
| `clipExempt` | 剖切豁免标记（塔、车、地面等） |
| CatmullRomCurve3 | 三维 Catmull-Rom 样条，用于车道路径与车辆补帧 |
| 后处理 / Post-processing | Bloom、色调映射等渲染后阶段；低帧率时自动关闭 |
| 像素比 / Pixel Ratio | 渲染分辨率倍率，低性能设备下调 |
| Store / AppActions | 前端单一状态源与「面板 → 应用层」动作契约，面板互不直接调用 |
| HUD | 底部 88px 操作条（时间轴、车流控件、图例） |
| 数值滚动 | 0.6s 从旧值过渡到新值，含千分位格式化 |
| Vite / TypeScript | 前端构建工具与严格类型语言 |

## 3. 后端、中间件与仿真术语

| 术语 | 含义 |
|---|---|
| Quarkus 3.8 | 本项目的 Java 云原生框架，JDK 17 |
| JAX-RS | `@Path` / `@GET` / `@POST` 等 REST 注解 |
| CDI / `@ApplicationScoped` | 依赖注入与单例 Bean 作用域 |
| SmallRye Health | `/q/health` 健康检查实现 |
| Micrometer / Prometheus | `/q/metrics` 指标暴露与抓取 |
| 统一响应 | `{code,msg,data,traceId}`，`code=0` 成功 |
| MQTT / QoS | 轻量发布订阅协议；QoS 0 至多一次、QoS 1 至少一次 |
| EMQX / ACL | MQTT Broker 与主题访问控制列表 |
| WebSocket / WSS | 前端经 Nginx `/mqtt` 代理连接 EMQX:8083；生产用加密 WSS |
| PostgreSQL / PostGIS | 关系库与空间扩展；SRID=0 平面米制 |
| JSONB | PG 二进制 JSON 类型，用于曲线控制点、相机关键帧、扩展字段 |
| 软删除 | `is_deleted` 标记，唯一索引多为 `WHERE is_deleted=false` 部分索引 |
| Redis TTL / LRU | 实时值 5 秒过期；`allkeys-lru` 内存淘汰策略 |
| TDengine 超级表 / 子表 / 标签 | `shm_metric` 稳定结构；每个测点一张子表；标签用于分组过滤 |
| MinIO / bucket / 预签名 URL | 对象存储、桶 `bridge-models`、临时授权下载链接 |
| SimPy | Python 离散事件仿真库，用于按车道泊松到达生成车辆 |
| 泊松到达 | 车辆到达间隔服从指数分布，速率随密度变化 |
| Paho MQTT | Python 与 Java 两侧使用的 MQTT 客户端库 |
| 清洗 | 校验测点编码、数值有限性、时间偏差；脏数据丢弃并计数 |
| 快照 | 每 2s 的整桥指标 + 150 测点状态，发布到 `realtime/bridge/*` |

## 6. 状态枚举速查

| 枚举 | 取值 | 出现位置 |
|---|---|---|
| 前端测点等级 `PointLevel` | `NORMAL` / `WARN` / `ALARM` | 传感器球体、热力着色、状态圆点 |
| 告警等级 `alarm_level` | `WARN` / `ALARM` / `SERIOUS` | 弹窗、告警列表 |
| 告警状态 `status` | `ACTIVE` / `CONFIRMED` / `IGNORED` / `RECOVERED` | 告警生命周期图 |
| 仿真状态 | `IDLE` / `RUNNING` / `STOPPED` / `FINISHED` | `sim_plan` |
| 数据模式 | `mock` / `live` | 顶栏状态、`VITE_DATA_MODE` |
| 视图 | `V1` 全景 / `V2` 结构 / `V3` 档案 | 顶栏视图按钮 |
